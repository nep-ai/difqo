# Contributing to Difqo

Difqo is in pre-MVP development. The most useful contributions right now are real examples of work you want to delegate, feedback on the [illustrated workflows](https://difqo.com/#use-cases), and fixes to this repository’s docs.

## Share feedback

- Search [open and closed issues](https://github.com/nep-ai/difqo/issues?q=is%3Aissue) for related reports.
- [Share a workflow](https://github.com/nep-ai/difqo/issues/new?template=workflow.yml) and tell us where you lose time or project context, plus what you’d need to see before accepting the work.
- [Report a problem](https://github.com/nep-ai/difqo/issues/new?template=bug.yml) with the website, examples, or docs. Use our [private reporting channel](SECURITY.md) for vulnerabilities.

Use sanitized examples in public issues and pull requests. Follow the [code of conduct](CODE_OF_CONDUCT.md).

## Open a pull request

1. For a feature or substantial change, open an issue and agree on scope with a maintainer before implementing. Small documentation fixes can go straight to a PR.
2. Fork the repo or create a branch from `main`. Keep the change focused and link the relevant issue in the PR.
3. Review the diff, check the links and examples you changed, and describe how you verified the result. Include screenshots or recordings when the change affects what users see.
4. If you used an AI coding tool, review its output yourself and disclose substantial generated changes in the PR. The submitter is responsible for correctness, attribution, and licensing.

By submitting a contribution, you agree to license it under the project’s [Apache License 2.0](LICENSE). Submit work you have the right to share.

See [how maintainers triage, review, and release changes](MAINTAINING.md).

If you use a coding agent, see [the repository's lifecycle skills](AGENTS.md#lifecycle-skills).
