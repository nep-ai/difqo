# Product discovery

- Start from the user's workflow. Identify the actor, their trigger, the job they do today, the friction, and the evidence they need to trust the result. Distinguish observed feedback from assumptions. Use the project README and any linked issues or decisions to establish current scope.
- For brainstorming, explore materially different ways to solve the problem. Compare user value, validation cost, and fit with the current milestone. Include a small way to learn whether the leading idea solves the problem.
- For a PRD, capture the problem and evidence, target user, desired workflow, scope and non-goals, success signal, acceptance scenarios, and unresolved decisions. Match the detail to the size of the change.
- For changes to agent handoffs, make success observable. Identify the project decision applied, the change it should affect, the evidence a user can rerun, and the choice the user can make with that evidence. Include a case where context or evidence is missing when it could change that choice.
